## TS스터디 19일차: 아이템 43~44 (5장)

이번 장에서는 `any`의 장점은 살리면서 단점을 줄이는 방법을 살펴본다.

### 아이템 43: any 타입은 가능한 한 좁은 스코프에서만 사용하기

```ts
const pizza = getPizza(); // pizza: Pizza

eatSalad(pizza); // 에러: Pizza는 Salad에 할당 불가

pizza.slice();
```

위 상황이 정상적으로 동작해야 한다면, 타입을 개선해야 한다.

이때 방법은 2가지인데,

```ts
// 1
const pizza: any = getPizza();

pizza.slice(); // any 타입이므로 체커 작동 X
```

```ts
// 2
eatSalad(pizza as any);

pizza.slice(); // 이 호출은 안전함
```

하나는 `pizza` 변수를 `any` 타입으로 하는 것, 또 다른 하나는 매개변수로 `pizza`를 전달할 때 `as any`를 사용하는 것

후자를 더 권장한다. 매개변수로 전달되는 부분에만 사용되었기 때문에 다른 코드에는 영향을 주지 않기 때문

`pizza` 자체를 `any`로 사용하면 체커도 작동하지 않고, 런타임 오류가 발생할 수 있다.

그렇다고 전자가 안전한 것도 아니다. 메서드 내에서는 `Pizza` 타입으로 남아 있지만, 사용되는 모든 곳에서는 `any` 타입이기 때문이다.

그래서 `any` 사용 스코프를 좁게 제한하면 위험성을 줄일 수 있다.

TS가 메서드의 반환 타입을 추론할 수 있어도, 명시하는 것이 좋다.

`any`의 영향을 막기 위해서!

그냥 오류만 제거해야 하는 경우, `@ts-expect-error`를 주석으로 달아서 지시할 수 있다.

오류를 제거하기 위해서 객체 전체를 `any`로 단언하면 다른 타입들 역시 체커가 작동하지 않는다. 그래서 최소한의 스코프에만 `any`를 사용하는 것이 좋다.

> any의 스코프를 최대한 줄여서 사용해라.

### 아이템 44: any를 구체적으로 변형해서 사용하기

일반적인 상황에서는 `any`보다 더 구체적으로 표현할 수 있을 가능성이 높다.

매개변수가 객체인데 값을 알 수 없는 상황이라면 `Record<string, any>` 또는 `object` 타입을 사용할 수 있다.

요소 타입이 중요하지 않다면 `any[]`보다는 `unknown[]`을 사용하는 것이 좋다.

## TS스터디 20일차: 아이템 45~46

### 아이템 45: 함수 안으로 타입 단언문 감추기

안전하게 작성된 함수 구현체 vs 내가 원하는 타입 시그니처

후자를 선택하는 것이 현명하다. 왜?

사용자에게 보이는 부분은 타입 시그니처이기 때문이다. 단언이나 `any` 타입은 가려지기 때문

#### 위 내용이 무슨 뜻일까?

```ts
function 함수이름(매개변수): 반환타입 {
  // 내부 구현
}
```

사용자는 보통 매개변수의 타입과 반환값의 타입에 신경 쓴다.

API 관련 메서드를 설명할 때는 여러 곳에서 타입 단언 처리를 하는 것보다는, 기존 시그니처를 유지하면서 구현체 내에서 타입 단언을 한 번만 하는 것을 보여준다.

예외 처리도 한 번만 수행하면 되니까 편하다.

위 내용이랑 반대 얘기 아닌가?

타입 단언문이 등장하는 곳에서는 단위 테스트를 더욱 수행해야 한다.

타입 체커의 믿음을 우리의 책임으로 돌렸기 때문에!

> 결론적으로는 타입 체커의 문제를 어쩔 수 없는 방법으로 해결할 때는, 함수 시그니처를 유지하고 `any`처럼 열어놓지 말고 구현체에서 스코프를 좁혀서 사용하자.

### 아이템 46: 타입을 모르는 경우 any 대신 unknown 사용하기

함수의 반환값이 `any`인 경우, 차라리 `unknown`을 사용하자.

왜? `any`의 경우 어떤 타입이든 `any`에 할당 가능하고, `any`는 어떤 타입으로도 할당 가능하기 때문이다.

위가 왜 문제가 될까?

타입이라는 시스템의 원칙에 정확히 상충되는 개념이기 때문

`unknown`은 위의 두 번째 특징은 만족하지 않는다. `unknown`은 `unknown`과 `any`에만 할당 가능하다.

그러나 `unknown` 타입인 채로 값을 사용하면 오류가 발생한다. 그래서 타입 단언을 사용해줘야 한다.

`instanceof`, 사용자 정의 타입 가드로도 타입 변환 가능

결국 바로 오류를 발생시킨다는 측면에서 `any`보다 안전하다.

> 어떤 값이 있지만 그 타입을 알지 못하는 경우 `unknown`을 사용하자.
