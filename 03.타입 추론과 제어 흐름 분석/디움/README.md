타입스크립트는 타입 추론을 적극적으로 수행한다.
타입 추론은 타입 구문의 수를 줄여 주기 때문에 코드의 전체적인 안전성이 향상된다.

## 아이템 18

타입 구문을 많이 사용할 필요는 없다.

-> 코드의 모든 변수에 타입을 선언하는 것은 비생산적이다.

```ts
function logProduct(product: Product){
	const {id, name, price} = product;
	...
}
```

구조 분해 할당을 사용해 각 지역 변수가 알아서 추론되도록 구현하는 것이 좋은 방법이다.

명시적 타입 구문은 **정보가 부족해서 타입스크립트가 스스로 타입을 판단하기 어려운 상황**에 사용한다.

### 타입을 명시해야 하는 경우

1. 객체 리터럴
타입 추론이 충분히 가능하지만 **객체 리터럴을 정의할 때**는 타입을 명시하자.
-> 잉여 속성 체크가 동작하기 때문이다.

2. 함수의 반환 타입
함수의 반환 타입을 명시하면, 내부 구현의 오류가 사용자 코드의 오류도 표시되지 않는다.
특히 return이 여러 개 존재하는 함수에 적용하면 좋은 방법이다.

타입을 명시한다는 것은 타입 추론이 필요 없다는 의미이다. 즉, 컴파일 성능에도 영향을 줄 수 있다.

## 아이템 19

**변수의 값은 바뀔 수 있지만, 그 타입은 바뀌지 않는다.**

타입을 바꿀 수 있는 단 한 가지 방법은 타입을 좁히는 것이다.

다른 타입에는 별도의 변수를 사용하자
- 서로 관련이 없는 두 개의 값을 분리한다.
- 변수명을 더 구체적으로 지을 수 있다.
- 타입 추론을 향상시키며, 타입 구문이 불필요해진다.
- 타입이 간결해진다.

목적이 다른 곳에는 별도의 변수명을 사용하는 것이 좋다.

## 아이템 20

타입 넓히기 : 구체적인 타입을 더 일반적인 타입으로 추론하는 것

``` ts
let x = "x"; // string
let num = 39; // number
let bool = true // boolean
```

타입 넓히기를 제어하는 방법 -> const로 변수를 선언한다.
const로 선언하면 재할당이 불가능하므로 타입스크립트는 더 좁은 타입으로 추론할 수 있다.

타입스크립트의 기본 동작을 재정의(= 개발자가 더 구체적인 타입을 직접 지정)하는 방법
- 명시적 타입 구문 제공
- 타입 체커에 추가적인 문맥 제공
- const 단언문 사용(as const)
- satisfies 연산자

as const 대신 satisfies를 사용하면 객체를 정의하는 시점에서 오류를 알 수 있다.

## 아이템 21

객체를 생성할 때는 속성을 하나씩 추가하기보다는 여러 속성을 포함해서 한꺼번에 생성해야 타입 추론에 유리하다.

객체들을 조합할 때 스프레드 연산자를 사용하면 큰 객체를 한꺼번에 만들어 낼 수 있다.

조건부 속성을 안전하게 추가하려면
-> 부정에 해당하는 값들 또는 {}를 사용하면 된다.
``` ts
const user = {
  name: '이름',
  ...(isAdmin ? { role: 'admin' } : {}),
};
```

## 아이템 22

타입 좁히기 : TS가 넓은 타입으로부터 좁은 타입으로 추론해 나가는 것

타입 체커는 조건문에서 타입 좁히기를 잘 해내지만, 타입 별칭이 존재하면 타입 좁히기를 못할 수도 있다.

타입스크립트의 심벌은 특정 위치에서 특정 타입을 가진다.
``` ts
function print(value: string | number) {
  // 이 위치의 value 타입: string | number

  if (typeof value === 'string') {
    // 이 위치의 value 타입: string
    console.log(value.toUpperCase());
  } else {
    // 이 위치의 value 타입: number
    console.log(value.toFixed());
  }

  // 이 위치에서는 다시 string | number
}
```

선언된 타입은 계속 `string | number`지만, TypeScript는 현재까지의 실행 흐름을 분석해서 특정 위치에서는 실제 타입을 더 구체적으로 판단한다 -> 제어 흐름 분석을 통한 타입 좁히기라고 한다.

타입 좁히는 방법
- 분기문에서 예외를 던지거나 함수 반환
- instanceof
- 속성 체크
- Array.isArray같은 내장 함수
- 명시적 태그 붙이기
- 사용자 정의 타입 가드

사용자 정의 타입 가드가 타입 단언보다 더 안전한 것은 아니다.
-> TS는 타입 가드 함수의 구현이 정말 올바른지 검증하지 않고, 개발자가 작성한 타입 서술어를 믿기 때문이다.

## 아이템 23

별칭을 남발해서 사용하면 제어 흐름을 분석하기 어렵다 -> 별칭은 일관성 있게 사용해야 한다.

**객체 비구조화**를 사용하면 간결하게 일관된 이름을 사용할 수 있다.
``` ts
const { name, age } = user;

console.log(name);
console.log(age);
```
객체의 속성 이름인 `name`, `age`가 그대로 지역 변수 이름이 돼서 코드가 간결해진다.

주의할 점 : 비구조화한 변수는 원본 프로퍼티와 별개의 값이므로 원본 객체가 변경되면 서로 달라질 수 있다.

-> 함수를 호출할 때 `readonly`를 사용해서 값의 변경을 방지하는 것이 좋다.

## 아이템 24

타입스크립트는 타입을 추론할 때 값이 존재하는 곳의 문맥까지 살핀다.

### 함수의 매개변수를 변수로 분리

```ts
type Language = 'JavaScript' | 'TypeScript' | 'Python';

function setLanguage(language: Language) {
  /* ... */
}

setLanguage('JavaScript'); // 정상

let language = 'JavaScript'; // 타입이 string으로 넓혀짐
setLanguage(language);
```

해결하는 방법
1. 타입 선언에서 할당 가능한 값을 제한 (let language: Language = 'JS')
2. const 사용

> [!tip]
> Q. 별도의 변수로 선언하는 것이 왜 문맥으로부터 값을 분리하는 것일까?
> 
> 값을 함수 안에 직접 쓰면 TS는 매개변수 타입을 문맥으로 활용해 해석한다.
> 
> 하지만 별도의 변수로 꺼내면 변수를 선언하는 시점에는 함수와 전혀 관련이 없어진다.

### 튜플 사용 시 주의점

```ts
function panTo(where: [number, number]) {}

const loc = [10, 20] as const;
panTo(loc);
```

`as const`를 사용하면 **과하게** 정확하다 -> readonly 타입이 되어버려 오히려 동작하지 않는다.

또한, 타입 정의를 할 때 실수를 한다면 오류는 호출되는 곳에서 발생한다 -> 원인을 파악하기 어렵다.

> [!note] 
> 인라인 형식이나 타입 정의 적용을 고려하자!
> ``` ts
> function panTo(where: readonly [number, number]) {}
> panTo([10, 20]); // 인라인 형식
> 
> function panTo(where: readonly [number, number]) {}
> const loc: readonly [number, number] = [10, 20];
> //       ^^^^^^^^^^^^^^^^^^^^^^^^^ 타입 정의 적용
> panTo(loc);
> ```

## 아이템 25

``` ts
function range(start: number, limit: number) {
	const nums = []; // any[]
	for(let i = start; i < limit; i++) {
		nums.push(i);
	}
	return nums; // number[]
}
```
nums의 타입이 처음엔 any[]지만, number 타입의 값을 넣는 순간부터 타입은 number[]로 진화한다.

any 타입의 진화는 any 타입에 **어떠한 값을 할당할 때만 발생**한다.

> [!note]
> 반복문에서의 타입 추론
> - 일반 `for`·`for...of`: 같은 제어 흐름 안에서 `push`하므로 `any[]`가 진화할 수 있음
> - `forEach`: `push`가 별도 콜백 함수 안에 있으므로 바깥 배열의 타입이 진화하지 않음
> - `map`: 결과 타입을 콜백 반환값으로 곧바로 추론하므로 이 경우 가장 깔끔함
