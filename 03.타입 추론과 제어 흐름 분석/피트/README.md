### 아이템 18: 추론 가능한 타입을 사용해 장황한 코드 방지하기

#### 내용 정리

TS에서 매번 타입을 선언하는 것은 비생산적이다 -> 타입 추론!

복잡한 객체도 추론할 수 있다.

구조분해 할당을 통해 각 지역 변수가 알아서 추론되도록 하는 것이 바람직하다.

주의할 점: 구조 분해 할당 내부에 타입을 직접 지정할 수 없음 <- 이름 변경의 의미로 알아먹기 때문에

메서드에 반환 타입을 명시하면, 내부 구현의 오류가 사용자 코드의 오류로 표시되지 않는다.

한 마디로 오류 위치를 정확하게 표시해준다.

반환 타입을 명시해야 하는 가장 큰 이유는 직관적인 표현 및 의도를 드러낸다는 점이다.

#### 궁금한 점

정보가 부족해서 스스로 타입을 추론하기 어려운 상황은 뭐가 있을까?

매개변수인 경우, 초기값이 없는 변수/배열, 외부 데이터, ...

any타입으로 추론된다.

### 아이템 19: 다른 타입에는 다른 변수 사용하기

중요한 점: 변수의 값은 바뀔 수 있지만, 그 타입은 보통 바뀌지 않는다.

#### 타입 지정 방법?

```ts
let value; // 처음엔 any처럼 보이지만...

if (Math.random() > 0.5) {
  value = 'hello';
  // 여기서 value: string
} else {
  value = 123;
  // 여기서 value: number
}

// 함수 밖으로 나오면
value; // value: string | number  ← 타입이 넓어짐
```

타입의 진화는 어디까지나 예외이지, 규칙이 아님

유니온을 쓰면 해결되지만, 다루기 더 어려워진다.

차라리 별도의 변수를 사용하자!

> let보다 const가 더 많아야 한다!!

타입이 바뀌는 변수를 지양해야 하기 때문

그렇다고 변수명이 같은데 타입이 다르면 사람에게 혼란을 줄 수 있다.

#### no-shadow 린터 규칙?

```ts
let x = 'outer';

function foo() {
  let x = 'inner'; // 바깥의 x를 "가림" (shadowing)
  console.log(x); // "inner"
}

foo();
console.log(x); // "outer" (바깥 x는 안 바뀜)
```

위 코드는 사용자에게 혼란을 줄 수 있음.

```ts
let x = 'outer';

function foo() {
  let x = 'inner'; // ❌ ESLint 에러: 'x' is already declared in the upper scope
}
```

린터 규칙을 통해 에러를 명시적으로 보여주기!

  ### 아이템 20: 변수의 타입이 결정되는 원리 이해하기
  - #### 내용
    - **런타임**에 모든 변수는 유일한 값을 가진다.
    - 그러나 TS의 정적 분석 시점에 변수는 타입을 가진다.
    - 타입을 명시하지 않으면 타입 체커는 타입을 결정해야 한다.
    - 즉, 지정된 값을 가지고 할당 가능한 값의 집합을 유추해야 한다는 뜻이다.
      - -> 타입 넓히기
  - 해석
    - #### 1. 런타임에는 변수가 "유일한 값"만 가짐
      - ```ts
        let x = 5;
        console.log(x); // 이 순간에는 x는 정확히 5라는 값 하나만 가짐
        ```
      - 프로그램이 실제로 실행될 때(런타임), 어느 한 시점에서 변수는 **딱 하나의 구체적인 값**만 가진다. (`x`가 5이면서 동시에 "hello"일 수는 없음)
    - #### 2. 그런데 TS는 "코드가 실행되기 전"에 미리 검사함
      - TS 컴파일러는 코드를 실행하지 않고 검사만 하는데, 이걸 "정적 분석"이라고 함.
      - 문제는, 코드를 실행 안 해봤으니 **"이 변수에 정확히 어떤 값이 들어올지"는 모른다**는 점이다.
      - ```ts
        let x = 5;
        ```
      - TS는 "이 코드를 실행하면 x가 정확히 5가 될 것"이라는 사실은 알지만, 확신할 수 있는 건 딱 그 순간까지고, **"x가 나중에 또 다른 값으로 바뀔 수도 있다"**는 가능성까지 대비해야 함.
    - #### 3. 그래서 "타입"이라는 걸 만들어서 대신 씀
      - TS는 "정확히 무슨 값인지"는 확정할 수 없으니, 대신 **"이 변수는 이런 부류의 값들 중 하나일 것"**이라는 **범위(집합)**로 표현해요. 그게 바로 "타입"!
      - ```ts
        let x = 5;
        // TS 입장: "x는 정확히 5"라고 딱 잘라 말하기보다
        // "x는 number 타입에 속하는 값 중 하나"라고 넓게 잡아둠
        ```
    - #### 4. 타입을 안 써주면, TS가 알아서 "적당한 범위"를 정해야 함
      - 5라는 값만 보고 5인지, number인지, any인지 어떻게 결정할까?
      - 그래서 적당히 넓혀서 타입을 결정한다. -> **타입 넓히기**!
  - #### 내용
    - 기본적으로 주어진 값으로 추론 가능한 타입이 여러 개이기 때문에, 과정이 상당히 모호하다.
    - let으로 할당된 기본형 값은 일반적으로 `기본 타입`으로 확장된다.
      - 넓히기 과정을 제어할 수 있는 가장 대표적인 방법은 `const` 선언이다.
    - 객체나 배열의 경우는 const로 해결되지 않는 경우가 있다.
    - 최대한 좁은 타입으로 추론하려면 `as const` 구문을 사용하자.
      - 이 문법은 타입 안전성을 해치지 않으므로 얼마든지 사용해도 된다.
    - `Object.freeze`도 타입 추론을 도와준다.
      - 추론된 타입을 `readonly`로 만들어준다.
      - 이 친구는 런타임 시점에 동작한다.
      - 그치만 얕게 작동한다.
    - 객체를 사용하는 위치가 아니라, 객체를 정의하는 시점에서 오류를 알 수 있기 때문에, `satisfies` 연산자가 `const` 단언문보다 낫다.
    - > 추론이 어떻게 변화하는지 주기적으로 타입을 살펴보자.

### 아이템 22: 타입 좁히기

타입 넓히기의 반대. 일반적인 예시는 `null` 체크

일반적으로 if문을 통해 검사하면 안정적이지만, 타입 별칭이 존재한다면 그러지 못할 수도 있다.

TS는 C++, 자바, 러스트와는 다르게 특정 위치에서 특정 타입을 가진다.

```ts
function getLength(elem: string | number) {
  if (typeof elem === 'string') {
    // 여기서 elem의 타입: string  ← 새 변수 안 만들었는데 저절로 좁혀짐!
    return elem.length;
  }

  // 여기서 elem의 타입: number  ← 아래로 내려오면 또 자동으로 좁혀짐
  return elem.toString().length;
}
```

null이 object임을 까먹지 말자. 예를 들어 `typeof elem === "object"`는 타입 좁히기가 안 됨!

### 아이템 23: 일관성 있는 별칭 사용하기

별칭을 남발하면 흐름을 추적하기 힘들다.

선택 속성을 지역 변수로 가져온 경우, 타입 좁히기가 생각대로 동작하지 않을 수 있다.

```ts
const box = polygon.bbox; // box의 타입: BoundingBox | undefined

if (polygon.bbox) {
  // 여기선 polygon.bbox가 undefined가 아님을 TS가 확인함 (narrowing 성공)
  // 하지만 box는요?
  box.x[0]; // ❌ 에러! box는 여전히 BoundingBox | undefined
}
```

그럼 box를 검사하면 되지 않을까?

타입 문제는 해결되지만, 코드를 읽는 사람에게 문제가 남아있다.

box와 bbox는 같은 값인데 다른 이름을 사용한 것이 문제이다.

객체 비구조화(구조분해할당)

```ts
function isPointInPolygon(polygon: Polygon, pt: Coordinate) {
  const { bbox } = polygon; // ① polygon에서 bbox를 바로 꺼냄

  if (bbox) {
    // ② bbox 자체를 체크 (별칭 문제 해결됨!)
    const { x, y } = bbox; // ③ bbox에서 x, y를 또 꺼냄

    if (pt.x < x[0] || pt.x > x[1] || pt.y < y[0] || pt.y > y[1]) {
      return false;
    }
  }

  // ...
}
```

주의할 점은 있다. `x`, `y` 값이 선택적일 경우는 추가적인 검사가 필요하다.

### 아이템 24: 타입 추론에 문맥이 어떻게 사용되는지 이해하기

타입 추론 시 값만 고려하지 않고, 값의 위치 문맥까지 파악한다.

문맥으로 인해 가끔 이상한 결과가 나옴

```ts
type Language = 'JavaScript' | 'TypeScript' | 'Python';

function setLanguage(language: Language) {
  /* ... */
}

setLanguage(' JavaScript'); // 정상

let language = 'JavaScript';

setLanguage(language); // 오류
// 'string' 형식의 인수는 'Language' 형식의 매개변수에 할당될 수 없습니다.
```

할당 시점에 타입을 검사하기 때문에, 인라인은 문제 없지만 변수로 따로 지정하면 오류 발생

타입을 변수에 지정해주거나 `const`를 쓰면 해결됨

but 튜플의 경우 `const`도 해결되지 않음

### 아이템 25: 타입의 진화 이해하기

타입은 변수 선언 시에 결정되며, 보통은 확장되지 않음

그러나 예외 상황이 존재한다. 타입의 진화!

암시적 `any` 상태인 변수에 어떠한 할당도 하지 않고 사용하려고 하면 `any` 오류가 발생한다.

타입의 흐름을 고려하면, `map`와 같은 내장 메서드를 사용하자.

> 타입을 안전하게 지키기 위해서 명시적 타입 구문을 사용하자!
