## 아이템 65 devDependencies에 typescript와 @types 추가하기

package.json 파일 내의 별도 영역에 `dependencies`, `devDependencies`, `peerDependencies`가 들어 있다.

### dependencies
현재 프로젝트를 실행하는 데 필수적인 라이브러리들이 포함된다. 다른 사용자가 해당 프로젝트를 설치한다면 depencies에 들어 있는 라이브러리들이 설치된다.

### devDependencies
현재 프로젝트를 개발하고 테스트하는 데 사용되지만, 런타임에는 필요 없는 라이브러리들이 포함된다.
(ex. wepback 환경 구축 패키지, 테스트 도구)

다른 사용자가 해당 프로젝트를 설치해도 여기에 포함된 라이브러리들은 제외된다.

-> `npm install` 시에는 설치되지만, 프로덕션 의존성만 설치하는 경우 제외된다.

### peerDependencies
런타임에 필요하지만 의존성을 직접 관리하지 않는 라이브러리들이 포함된다.

-> 무슨 말이냐면 이 프로젝트를 실행하기 위해선 React가 필요한데 여기에 설치되어 있지 않으니 사용하는 쪽에서 설치하라는 말이다.

일반적으로는 `dependencies`와 `devDependencies`만 사용된다. 타입스크립트와 관련된 라이브러리는 대부분 `devDependencies`에 속한다 -> 당연한 얘기다. 컴파일 과정에서 타입 정보는 없어지기 때문.

### 팁

TS를 시스템 레벨에서 설치하는 것은 추천하지 않는다. (시스템 레벨 = 컴퓨터 전역)

-> 너무 당연한 말

타입 의존성을 고려해야 한다.

-> 원본 라이브러리가 dependencies에 있어도 @types 의존성은 devDependencies에 있어야 한다.

## 아이템 66 타입 선언과 관련된 세 가지 버전 이해하기

라이브러리의 버전, @types의 버전, TS의 버전 셋 중 하나라도 맞지 않으면 오류가 발생할 수 있다. 이러한 오류의 원인을 파악하고 해결하기 위해서는 TS의 라이브러리 관리 메커니즘을 이해해야 한다.

> [!note]
`npm install --save-dev` , `npm install -D` 명령어는 `devDependencies`에 저장하라는 명령어이다.

실제 라이브러리와 타입 정보의 버전이 별도로 관리되는 방식은 문제점이 있다.
- 라이브러리를 업데이트했지만, 실수로 타입 선언은 업데이트하지 않는 경우
- 라이브러리보다 타입 선언의 버전이 최신인 경우
- 프로젝트에서 사용하는 타입스크립트의 버전보다 라이브러리에서 필요로 하는 타입스크립트 버전이 최신인 경우
- @types 의존성이 중복되는 경우

타입스크립트로 작성된 라이브러리는 자체적으로 타입 선언을 번들링한다.

이 경우 버전 불일치 문제는 해결되지만 문제점이 존재한다.
- 보강 기법으로 해결할 수 없거나 TS 버전이 올라가면서 오류가 발생하는 경우
- 프로젝트 내의 타입 선언이 다른 라이브러리의 타입 선언에 의존하는 경우
- 프로젝트의 과거 버전에 있는 타입 선언에 문제가 있는 경우
- 타입 선언의 패치 업데이트를 자주 하기 어려움

## 아이템 67 공개 API에 등장하는 모든 타입 익스포트하기

라이브러리의 타입이나 인터페이스를 사용해야 하지만 export 되어 있지 않은 경우 `Parameters` 와 `ReturnType` 제네릭 타입을 사용하면 타입을 추출해 낼 수 있다.

## 아이템 68 API 주석에 TSDoc 사용하기

사용자를 위한 문서라면 JSDoc 스타일의 주석을 사용하는 것이 좋다.

-> `//` 대신 `/**/` 사용하라는 것 같음

인라인 주석은 편집기가 주석을 표시해주지 않는다.

TSDoc 주석은 마크다운 형식을 지원한다. 하지만 장황하게 쓰지 말고 요점만 언급해야 한다.

주석에 타입 정보를 명시하면 안 된다.(타입 정보가 이미 코드에 있기 때문)
