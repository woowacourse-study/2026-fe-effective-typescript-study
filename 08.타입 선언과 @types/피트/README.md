## TS스터디 30일차: 아이템 65~66 (8장)

### 아이템 65: devDependencies에 TypeScript와 @types 추가하기

TS는 런타임에는 존재하지 않기 때문에 `devDependencies`에 속한다.

#### TS 프로젝트에서 공통으로 고려해야 하는 의존성 2가지

첫 번째는 TypeScript 자체이다.

TypeScript를 시스템에 전역으로 설치하면 개발자마다 어떤 버전을 설치할지 보장할 수 없다.

프로젝트의 `devDependencies`에 추가하면 프로젝트에서 사용하는 TypeScript 버전을 동일하게 유지할 수 있다.

두 번째는 타입 의존성이다.

`@types` 패키지를 통해 라이브러리의 타입 정보를 얻을 수 있다.

TS와 타입 의존성인 `@types` 패키지는 모두 `devDependencies`에 포함해야 한다.

### 아이템 66: 타입 선언과 관련된 세 가지 버전 이해하기

의존성 관리 힘들어용

실제로 TS는 의존성 문제를 해결하기는커녕 관리를 더 복잡하게 만든다.

왜?

라이브러리 버전, 타입 선언의 버전, TypeScript 버전을 추가로 고려해야 하기 때문이다.

세 개 중 하나라도 맞지 않으면 엉뚱한 오류가 발생할 수 있다.

보통 패치 버전인 `x.x.0`, `x.x.1` 등이 달라져도 공개 API의 사양은 변경되지 않는다.

그래서 메이저와 마이너 버전이 동일하다면 반드시 업데이트할 필요는 없지만, 기존 타입 선언에 버그가 존재할 수 있다.

버그나 누락된 타입의 수정으로 인해 패치 버전이 달라질 수 있기 때문이다.

#### 호환되지 않는 문제를 해결하는 방법

관련 라이브러리와 타입 선언의 버전을 업데이트하기

보강 기법을 사용해 타입 선언 보완하기

> 라이브러리, 타입 선언, TypeScript의 버전이 호환되지 않는다면 서로 일치하도록 만들어라.
