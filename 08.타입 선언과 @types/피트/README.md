#### TS 프로젝트에서 공통으로 고려해야 하는 의존성 2가지

첫 번째는 TypeScript 자체이다.

### 아이템 69: 콜백 함수에서 this에 대한 타입 제공하기

JS에서 `this`는 재앙이다.

`let`이나 `const`는 렉시컬 스코프를 따르지만, `this`는 다이내믹 스코프를 따르기 때문이다.

렉시컬 스코프는 변수가 작성된 위치를 기준으로 값을 찾는다.

반면 `this`는 코드가 작성된 위치가 아니라 함수가 호출된 방식에 따라 값이 달라진다.

```ts
class C {
  vals = [1, 2, 3];

  logSquares() {
    for (const val of this.vals) {
      console.log(val ** 2);
    }
  }
}

const c = new C();
c.logSquares();
```

위 코드의 실행 결과는 `1 4 9`이다.

그런데 `c.logSquares`를 외부 변수에 넣고 호출하면 어떻게 될까?

```ts
const method = c.logSquares;

method();
// 런타임 에러: undefined의 vals 속성을 읽을 수 없음
```

기존의 `c.logSquares()`는 두 가지 일을 한다.

`C.prototype.logSquares`에 있는 메서드를 호출한다.

메서드 내부의 `this`를 `c`로 바인딩한다.

그런데 `logSquares`의 참조만 변수에 저장하면 메서드와 객체의 연결이 끊긴다.

이후 `method()`로 호출하면 어떤 객체를 통해 호출한 것이 아니므로 `this`가 `undefined`가 된다.

#### this 바인딩을 직접 제어하는 방법

`call`을 사용하면 함수가 실행될 때 사용할 `this`를 직접 지정할 수 있다.

```ts
const method = c.logSquares;

method.call(c);
```

#### 클래스에서 this 바인딩 유지하기

클래스 메서드를 외부로 전달하면 `this`가 `undefined`가 될 수 있다.

생성자에서 메서드에 `this`를 바인딩하면 이를 방지할 수 있다.

```ts
class C {
  vals = [1, 2, 3];

  constructor() {
    this.logSquares = this.logSquares.bind(this);
  }

  logSquares() {
    for (const val of this.vals) {
      console.log(val ** 2);
    }
  }
}
```

또는 클래스 메서드를 화살표 함수로 정의할 수 있다.

```ts
class C {
  vals = [1, 2, 3];

  logSquares = () => {
    for (const val of this.vals) {
      console.log(val ** 2);
    }
  };
}
```

콜백 함수의 첫 번째 매개변수로 선언된 `this`는 TS에서 특별하게 처리된다.

실제로 전달되는 매개변수가 아니라, 콜백을 호출할 때 어떤 타입의 값이 `this`에 바인딩되어야 하는지 검사하는 용도이다.

### 아이템 70: 의존성 분리를 위해 미러 타입 사용하기

각자가 필요한 모듈만 사용할 수 있도록 하려면 구조적 타이핑을 적용할 수 있다.

필수가 아닌 의존성을 분리할 때 사용하는 방법이다.

외부 타입에서 실제로 사용하는 구조만 별도의 타입으로 다시 정의하는 것을 미러 타입이라고 한다.

공개한 라이브러리를 사용하는 JS 사용자가 불필요하게 `@types` 의존성을 가지지 않게 해야 한다.

같은 맥락으로 TS 웹 개발자가 불필요하게 Node.js 타입 의존성을 가지지 않게 해야 한다.

구조적 타이핑을 활용하면 외부 라이브러리의 전체 타입을 직접 참조하지 않고도, 필요한 속성만 가진 미러 타입을 정의해 사용할 수 있다.

> 필수가 아닌 타입 의존성이 라이브러리 사용자에게 전파되지 않도록, 필요한 구조만 표현한 미러 타입을 사용하자.
